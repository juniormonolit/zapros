# Архитектура: обзор zapros

**Дата:** 2026-06-01  
**Статус:** Утверждено для MVP

## Цель продукта

Сотрудники снабжения публикуют **запросы** поставщикам; поставщики отвечают ценами, сроками и наличием. Снабженец сравнивает ответы и ведёт запрос до исхода: **победа** (выбран поставщик) или **брак** (с понятной причиной).

## Ключевые сущности

```text
Задача (Task)          — родитель, импорт из Bitrix (все позиции, метаданные)
    └── Запрос (Request) — дочерний, подмножество позиций + рассылка поставщикам
            └── Приглашение (RequestSupplier) — пара запрос–поставщик
                    └── Версии ответа (SupplierResponseVersion)
```

- **Задача** — один paste из Bitrix, уникальный номер задачи Bitrix.
- **Запрос** — создаётся из задачи: снабженец выбирает позиции, превью, выбирает поставщиков, отправляет.
- **Приглашение** — изоляция: поставщик видит только свой тред и свой ответ; не видит других поставщиков на том же запросе.

Дублирование **одной позиции** в нескольких активных запросах одной задачи **разрешено** (сравнение предложений).

## Стек

| Слой | Технология |
|------|------------|
| Frontend | Next.js 15 App Router, TypeScript, Tailwind, shadcn/ui |
| Backend / DB | Supabase (PostgreSQL, Auth, RLS) |
| Auth | Supabase Auth + `profiles` с ролью |
| Cron / таймеры | Supabase Edge Function или pg_cron (10 кал. дней, настраивается) |
| Деплой (рекомендация) | Vercel + Supabase Cloud |

## Две доски снабженца

1. **Задачи** — список/канбан задач, счётчик запросов: завершено / в работе / всего.
2. **Запросы** — канбан по стадиям запроса + табличный вид с фильтрами (как Bitrix).

## Доска поставщика

Канбан по **приглашению** (`request_supplier`), не по глобальному запросу.

## Интеграция Bitrix

- Только **copy-paste** текста задачи (без API в MVP).
- Ссылка на задачу: шаблон из настроек `bitrix_group_settings` + `{task_id}`.
- Пример текущей группы: `мск_Утеплитель` → `https://td.monolit-crm.ru/workgroups/group/17/tasks/task/view/{task_id}/`

## Безопасность (принципы)

- RLS на всех таблицах с данными запросов и ответов.
- `service_role` только на сервере (Server Actions, Route Handlers, cron).
- Поставщикам не отдаются: «Наша цена», «Цена конкурента» из Bitrix.
