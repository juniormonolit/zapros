# План: Фаза 2.6 — Парсер реального формата + роль `senior_procurement` + модель поставщиков (groundwork)

**Создан:** 2026-06-02
**Оркестрация:** orch-2026-06-02-14-44-sourcing
**Статус:** 🟢 Ready
**Документы:** F001, F010, data-model.md, auth-rls.md
**Платформа:** Windows / PowerShell (команды через `;`, не `&&`)
**Миграции:** только раннером `npm run db:migrate -- supabase/migrations/<file>.sql` (Supabase MCP недоступен)

## Цель

Заложить фундамент под старшего снабженца и проработку поставщиков, **без** канбана `/sourcing`
(стадии воронки уточняются позже, F010 — черновик). В этом цикле:

1. Парсер `parseBitrixPaste` понимает реальный построчный «тире-формат» Bitrix (пример 113881),
   не ломая существующий табличный формат A (113153). Автовыбор формата.
2. Миграции: роль `senior_procurement`, enum `supplier_sourcing_status`, контактные поля и
   стадия у `suppliers`, бэкафилл существующих строк, RLS под новую роль.
3. Роль `senior_procurement` в auth/middleware/роутинге (сегмент `/sourcing` — заглушка).
4. Admin: провижининг новой роли + минимальный CRUD контактов/стадии поставщика.

## Ключевые архитектурные решения

- **Single source of truth для `works_in_zapros`** — стадия `sourcing_status`. В server actions:
  установка `sourcing_status = 'working_in_zapros'` ⇒ `works_in_zapros = true`; любой уход из этой
  стадии ⇒ `works_in_zapros = false`. Флаг — только для быстрых выборок/фильтров.
- **Производные правила (для будущей Фазы 3, фиксируем сейчас в RLS/коде):**
  `available_for_selection = sourcing_status in ('approved','working_in_zapros') and is_active`.
- **Парсер чистый и тотальный** — без БД/сети/`Date.now()`, не бросает; цены/суммы НЕ импортируются
  ни в формате A, ни в формате B.
- **Миграции идемпотентны** — `ALTER TYPE ... ADD VALUE` под guard (проверка `pg_enum`),
  `add column if not exists`, `drop policy if exists`→`create policy`, хелперы `create or replace`.
- **`ALTER TYPE ADD VALUE` нельзя в одной транзакции с использованием значения** — новое значение
  enum (`senior_procurement`) добавляем в 006, а его использование (бэкафилл/политики) — после
  коммита (раннер выполняет файл, новое значение становится доступно для последующих файлов/запросов).
  Чтобы избежать ошибки «unsafe use of new value», бэкафилл `working_in_zapros` использует НОВЫЙ
  enum `supplier_sourcing_status` (создаётся целиком в этой же миграции — безопасно), а значение
  роли `senior_procurement` в этой миграции только добавляется и НЕ используется в DML.

## Задачи (детально)

### SRC-001 — Парсер: формат B («тире-формат») + автовыбор

- **Приоритет:** High
- **Сложность:** Moderate
- **Зависимости:** нет
- **Требует unit-тестов:** ДА (см. SRC-002, test-writer)
- **Файлы/области:**
  - `src/lib/parser/bitrix.ts` — `parseBitrixPaste` и новые приватные хелперы парсинга формата B.
- **Описание:**
  Научить парсер понимать построчный формат Bitrix (пример 113881), сохранив формат A (113153).
  - **Автовыбор формата:** если в блоке после `Продукция из товаров:` есть табличный заголовок
    с колонкой «Товар» (таб-разделённый) → формат A (текущая логика). Иначе → формат B.
    Если маркер `Продукция из товаров:` отсутствует, но есть строки «тире-формата» — тоже формат B
    (учесть: в реальном пейсте 113881 секция товаров может идти без табличного заголовка).
  - **Формат B (строка):** `<Товар> - <Кол-во> <Ед> - <цена> руб/ед - <сумма> руб`.
    Разделитель полей — ` - ` (пробел-дефис-пробел). Импортируем **только**:
    `name` (1-е поле), `quantity` + `unit` (2-е поле, через существующий `parseQuantity`).
    Поля с ценой/суммой (`руб/ед`, `руб`) **не импортируются**.
  - **Конец таблицы (формат B):** маркеры `Итого:`, `Цена которую предлагают конкуренты:`
    (и существующие `Общая сумма`, `добавить чек-лист`). Вынести список маркеров в константу.
  - Имя товара может содержать запятые/числа (`маты прошивные МП 50, 100 мм`) — сплит строки
    делать строго по ` - ` и брать первое поле как имя; не путать с дефисами внутри имени без
    окружающих пробелов.
  - Строки без второго поля количества → `quantity=null`, имя сохраняем (тотальность парсера).
  - Не ломать публичный тип `ParsedTaskItem` / `ParsedTaskPreview`.
- **Критерии приёмки:**
  - [ ] `parseBitrixPaste` на пейсте 113881 даёт строки с корректными `name`/`quantity`/`unit`,
        без ценовых полей; строка-пример `маты прошивные МП 50, 100 мм - 1.0000 упак - 0.00 руб/упак - 0 руб`
        → `{ name: "маты прошивные МП 50, 100 мм", quantity: 1, unit: "упак" }`.
  - [ ] Формат A (113153) продолжает давать те же 4 строки (регрессии нет).
  - [ ] Маркер `Итого:` корректно завершает таблицу формата B.
  - [ ] Цены/суммы не попадают ни в `name`, ни в `comment`, ни в `unit`.
  - [ ] Функция остаётся чистой и не бросает на «мусорном» вводе.

### SRC-003 — Миграция 006: enum роли, enum воронки, поля `suppliers`, бэкафилл

- **Приоритет:** High
- **Сложность:** Moderate
- **Зависимости:** нет (первая в БД-ветке)
- **Файлы/области:**
  - `supabase/migrations/006_sourcing_supplier_fields.sql` (новый)
  - Применение: `npm run db:migrate -- supabase/migrations/006_sourcing_supplier_fields.sql`
- **Описание:**
  - **Роль:** `alter type public.user_role add value if not exists 'senior_procurement';`
    Порядок значений: для совместимости разместить между `admin` и `procurement`
    (`add value 'senior_procurement' before 'procurement'`) — guarded проверкой наличия в `pg_enum`
    (использовать `if not exists` где доступно; иначе `do $$ ... $$` с проверкой). Значение роли в
    DML этой миграции **не используется** (см. архитектурное замечание про `ADD VALUE`).
  - **Enum воронки:** `create type public.supplier_sourcing_status as enum
    ('new','called','clarified','got_price','test_order','approved','working_in_zapros','rejected');`
    под guard (`do $$ if not exists (select 1 from pg_type where typname=...) then create type ...`).
  - **Поля `suppliers`** (`add column if not exists`):
    - `sourcing_status public.supplier_sourcing_status not null default 'new'`
    - `works_in_zapros boolean not null default false`
    - `contact_person text`
    - `phone text`
    - `email text`
    - `notes text`
    - `created_by uuid references public.profiles(id) on delete set null`
  - **Бэкафилл существующих:** активные поставщики (`is_active = true`) →
    `sourcing_status = 'working_in_zapros'` и `works_in_zapros = true` (чтобы текущий выбор
    поставщиков в системе не сломался). Неактивные оставить на дефолте (`new`/false) или
    `rejected` — выбрать `new`+false (минимально-инвазивно). Бэкафилл идемпотентен (повторный
    запуск не портит данные: обновлять только строки, где значение ещё дефолтное, или безусловный
    `update ... where is_active = true`).
  - **Индекс (рекомендация):** частичный индекс под выборку доступных поставщиков:
    `create index if not exists suppliers_available_idx on public.suppliers (sourcing_status)
     where is_active;`
- **Критерии приёмки:**
  - [ ] `npm run db:migrate -- supabase/migrations/006_...sql` проходит без ошибок; повторный
        запуск тоже (идемпотентность).
  - [ ] В `public.user_role` присутствует значение `senior_procurement`.
  - [ ] Создан enum `supplier_sourcing_status` со всеми 8 значениями.
  - [ ] У `suppliers` появились новые поля с корректными дефолтами.
  - [ ] Активные поставщики имеют `sourcing_status='working_in_zapros'` и `works_in_zapros=true`.
