# План MVP: zapros

**Дата:** 2026-06-01  
**Стек:** Next.js 15 + Supabase  
**Оценка:** прототип / MVP (итеративно)

## Цель MVP

Рабочий цикл: paste Bitrix → задача → запрос → ответы поставщиков → сравнение → победа/брак. Три роли, две доски снабженца, канбан поставщика, треды, таймер 10 р.д.

## Вне scope

- Файлы, вложения
- Аналитика и дашборды
- Экспорт Excel
- API Bitrix
- Email/push (поля для аналитики заложить)
- Снятие победителя
- Сохранённые пресеты фильтров

## Порядок миграций Supabase

1. `001_enums_profiles.sql` — enums, profiles, триггер создания профиля, индекс единственного admin
2. `002_suppliers_groups.sql`
3. `004_tasks_items.sql` (вместо 003)
4. `005_tasks_rls.sql` (вместо 004)
5. `006_sourcing_supplier_fields.sql` — роль senior_procurement, enum sourcing_status, поля suppliers
6. `007_suppliers_sourcing_rls.sql` — RLS suppliers, хелпер is_senior_or_admin()
7. `008_sync_supplier_works_in_zapros.sql` — триггер синхронизации works_in_zapros (укрепление по code-review)
8. `009_requests.sql` — request_code, статус cancelled
9. `010_responses.sql` — CHECK-констрейнты (XOR наличие/срок, доставка)
10. `011_events.sql`
11. `012_app_settings_notifications.sql` — app_settings, notifications, поля уведомлений в profiles
12. `013_rls_policies.sql` — RLS, блокировка ответа в финальных статусах
13. `014_views_counters.sql` (optional)

## Критерий готовности MVP

- [ ] Снабженец проходит полный цикл на тестовых данных (задача 113153)
- [ ] 2 поставщика на одном запросе не видят ответы друг друга
- [ ] Таймер срабатывает на тестовом invite (можно сократить в dev)
- [ ] Админ создаёт поставщика и снабженца
- [ ] Победа закрывает запрос, проигравшие с одной причиной
