# F005: Канбан и фильтры

**Дата:** 2026-06-01  
**Статус:** MVP

## Цель

Две доски для снабженца (задачи + запросы), одна доска для поставщика (по invite). Табличный вид с фильтрами как в Bitrix. Проигранные стадии скрыты по умолчанию.

## Доски снабженца

### 1. Задачи

- Колонки по `tasks.status` или список с бейджами.
- На карточке: номер Bitrix, title, category, счётчик запросов (завершено / в работе / всего).
- Действия: открыть, новая задача (paste), поиск.

### 2. Запросы

Колонки (видимые по умолчанию):

- Новый
- Ожидаем ответы
- Есть ответ
- На уточнении
- В работе

Скрытые (группа «завершённые»):

- Не прошли
- Завершён (победа)
- Без ответа

Drag-and-drop смена статуса (где ручной переход разрешён).

### 3. Таблица запросов

Те же данные, что канбан, с сортировкой и фильтрами.

## Доска поставщика

Колонки по `request_suppliers.status`:

- Новый запрос
- Дан ответ
- На рассмотрении
- На уточнении
- В работе
- Не прошли (скрыто по умолчанию)
- Без ответа (скрыто)

Карточка: номер Bitrix (показываем поставщику) + `request_code`, позиции, дедлайн, статус.

## Фильтры (MVP)

| Фильтр | Применение |
|--------|------------|
| Дата создания | диапазон |
| Дата завершения | диапазон |
| Группа стадий | по умолчанию «Запрос в работе» |
| Статус | мультивыбор |
| Ответственный | created_by (для снабженца — только я) |
| Поставщик | по invite |
| Категория | category задачи |
| Номер Bitrix | точный / contains |

Кнопки: «Применить», «Сбросить», «Показать завершённые».

Сохранённые пресеты фильтров — **фаза 2**.

## Пустые состояния

- Нет задач → CTA «Создать из Bitrix»
- Нет запросов в колонке → подсказка
- Поставщик: нет новых → «Все запросы обработаны»

## Адаптив

Поставщики часто с телефона — карточки и фильтры в drawer на mobile.

## Критерии приёмки

- [ ] По умолчанию не видны won/lost/no_response
- [ ] Фильтр «Запрос в работе» восстанавливает дефолт
- [ ] Таблица и канбан показывают одни и те же запросы (разный вид)
- [ ] Снабженец видит только свои задачи/запросы
