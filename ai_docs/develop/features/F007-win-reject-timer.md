# F007: Победа, брак, таймер

**Дата:** 2026-06-01  
**Статус:** MVP

**Принцип MVP: «1 запрос = 1 победитель».** Разные поставщики по разным позициям → разные запросы.

## Победа

1. Снабженец на запросе с ≥1 ответом выбирает **победителя** (`request_supplier`).
2. Запрос: `status = won`, `outcome = won`, `winning_*` заполнены.
3. Остальные invites: `status = lost`, одна `reject_reason` на всех (выбор из enum + опциональный текст).
4. **Отменить победу нельзя** в MVP.
5. `task_items` по строкам запроса → `line_status = closed`.
6. **Автозакрытие дублей:** другие открытые запросы с теми же `task_item` → `status = cancelled`, `outcome = cancelled`; их invites → `lost` (`other_supplier_selected`); событие в лентах.

## Брак без победителя

- Запрос → `lost`, `outcome = lost`, причина обязательна.
- Все invites → `lost` с той же причиной.

## Таймер «Без ответа»

| Параметр | Значение |
|----------|----------|
| Объект | `request_suppliers` |
| Срок | **10 календарных дней** (праздники/выходные не учитываем) |
| Настройка | `app_settings.response_deadline_days`, дефолт 10 |
| TZ | Europe/Moscow |
| Старт | `sent_at` при создании invite |
| Пауза | Статус `clarification` — таймер на паузе |
| Результат | invite `status = no_response`, event; пустой запрос → архив |

### Расчёт deadline

```text
deadline_at = sent_at + (app_settings.response_deadline_days * interval '1 day')
```

При снятии с паузы (`clarification` → дальше): продлить `deadline_at` на длительность паузы.

### Cron

- Ежедневно (напр. 09:00 MSK): выбрать invites где `now() > deadline_at` AND status ожидает ответ AND timer not paused.
- Обновить статус на `no_response`, записать event.

## Агрегация на запросе

- Если **все** invites `no_response` и ни одного ответа → запрос `no_response` и уходит в архив (скрыт из рабочего канбана).
- Если часть ответила, часть нет — запрос остаётся `has_response` / `awaiting_responses`, только invite без ответа → `no_response`.

## UI

- Бейдж «До ответа: N дн.» на карточке поставщика.
- Красный бейдж при просрочке.
- Диалог победы: выбор поставщика + причина для остальных (один select).

## Критерии приёмки

- [ ] Через `response_deadline_days` календарных дней без ответа → no_response
- [ ] Пустой по ответам запрос после таймера уходит в архив
- [ ] На уточнении дедлайн не уменьшается (пауза)
- [ ] Победа блокирует снятие
- [ ] Проигравшие получают одну выбранную причину
- [ ] Победа автозакрывает дубли позиций в других открытых запросах
