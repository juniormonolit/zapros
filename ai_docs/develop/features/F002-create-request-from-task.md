# F002: Создание запроса из задачи

**Дата:** 2026-06-01  
**Статус:** MVP

## Цель

Из **Задачи** снабженец выбирает подмножество товаров → создаёт **Запрос** (черновик) → превью → выбор поставщиков → отправка.

## User stories

1. Как снабженец, я отмечаю галочками позиции в задаче и нажимаю «Создать запрос».
2. Как снабженец, я проверяю превью запроса и комментарий к запросу.
3. Как снабженец, я указываю, нужна ли доставка (флаг для ответа поставщика).
4. Как снабженец, я отправляю запрос выбранным поставщикам.
5. Как снабженец, я вижу на задаче счётчик: завершено / в работе / всего запросов.
6. Как снабженец, я могу создать второй запрос с теми же позициями (дубли разрешены).

## Flow

```text
Карточка задачи
  → чекбоксы task_items
  → «Создать запрос»
  → requests.status = draft
  → превью (редактирование comment, needs_delivery)
  → F003 выбор поставщиков
  → «Отправить»
  → request_items snapshot, request_suppliers[], sent_at, таймеры
  → requests.status = new → awaiting_responses
  → task_items.line_status = in_request (для выбранных)
```

## Черновик

- `draft` можно сохранить и вернуться позже.
- Добавление поставщиков до отправки (F003).

## После отправки

- Редактирование позиций — только через сценарий «уточнение» (событие `request_updated` + история в events).
- Добавление поставщиков после отправки — **да** (новые `request_supplier` со своим таймером).

## Счётчик на задаче

| Метрика | Правило |
|---------|---------|
| Всего | COUNT(requests) по task_id |
| В работе | status ∉ финальных |
| Завершено | outcome IS NOT NULL или status ∈ {won, lost, no_response, cancelled} |

## Автозакрытие дублей при победе

Дубли позиций между запросами разрешены, но при победе одного запроса другие открытые запросы с теми же `task_item` **автоматически закрываются** (`cancelled`). См. F007 и status-machines.md.

## Дополнительно MVP

- **Копия запроса** — новый draft с теми же items и другим набором поставщиков.
- **Поиск** по номеру Bitrix / названию сделки (глобальный поиск снабженца).

## Критерии приёмки

- [ ] Запрос без позиций нельзя отправить
- [ ] Snapshot названия/кол-ва/ед. на request_items
- [ ] После отправки поставщики видят новый invite
- [ ] Счётчик на карточке задачи обновляется

## Зависимости
