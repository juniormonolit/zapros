# F004: Варианты ответа поставщика

**Дата:** 2026-06-01  
**Статус:** MVP

## Цель

Поставщик заполняет ответ по строкам запроса: до **трёх вариантов цены**, доставка, наличие **или** срок, комментарии. Поддержка **версий** ответа с видимой историей.

## User stories

1. Как поставщик, я отправляю ответ с ценами по каждой строке.
2. Как поставщик, я указываю до трёх типов цены (не обязаны все):
   - **нал** (`price_cash`) — оплата наличными;
   - **безнал с НДС** (`price_with_vat`);
   - **безнал без НДС** (`price_without_vat`).
3. Как поставщик, при необходимости доставки я указываю сумму доставки ИЛИ «цена с доставкой».
4. Как поставщик, по строке я указываю либо наличие, либо срок поставки.
5. Как поставщик, я отправляю новую версию ответа; старая остаётся в истории.
6. Как снабженец, я вижу все версии и понимаю, какая актуальная (`is_current`).

## Поля по строке (`response_line_items`)

| Поле | Тип | Правило |
|------|-----|---------|
| `price_with_vat` | money nullable | Опционально |
| `price_cash` | money nullable | Скрыто если запрос `non_cash` only |
| `price_without_vat` | money nullable | Опционально |
| `delivery_price` | money nullable | XOR с `price_includes_delivery` |
| `price_includes_delivery` | boolean | Цена уже с доставкой |
| `in_stock` | boolean nullable | XOR `lead_time_days` |
| `lead_time_days` | int nullable | XOR `in_stock` |
| `line_comment` | text nullable | |

## Уровень версии

| Поле | Описание |
|------|----------|
| `comment` | Комментарий к ответу целиком |
| `version_number` | 1, 2, 3… |
| `is_current` | Одна активная на invite |
| `submitted_at` | |

При новой версии: предыдущая `is_current = false`.

## Ограничение формы оплаты запроса

| `requests.payment_form` | Доступные поля цены |
|-------------------------|---------------------|
| `cash` (нал) | with_vat, cash, without_vat |
| `non_cash` | with_vat, without_vat (**без** cash) |

## Доставка

- На запросе: `needs_delivery = true` → показывать блок доставки в ответе.
- `needs_delivery = false` (самовывоз) → блок доставки скрыт.

## UI снабженца: сравнение

Таблица: строки запроса × поставщики (только свои invites), в ячейке — актуальная версия, раскрытие истории.

### Нормализация для «лучшего»

Показываем все заполненные варианты, но для сортировки/подсветки приводим к безналу:

```text
безнал_эквивалент(нал) = price_cash / cash_to_noncash_ratio   # дефолт 0.84 → ~+16%
сравнительная_цена = min(price_without_vat, price_with_vat, price_cash / ratio)
```

- Коэффициент берётся из `app_settings.cash_to_noncash_ratio`.
- Подсветка лучшей цены по строке и итог по поставщику — справочно; финальный выбор за снабженцем.

## После отправки ответа

- Invite: `new` → `answered`
- Запрос: при первом ответе → `has_response`
- Event: `response_submitted`
- `first_response_at` если первый раз

## Критерии приёмки

- [ ] Нельзя указать и `in_stock` и `lead_time_days` на одной строке
- [ ] Нельзя указать и `delivery_price` и `price_includes_delivery`
- [ ] Версия 2 становится current, версия 1 в истории
- [ ] При non_cash поле cash недоступно
