# F003: Дерево поставщиков и приглашения

**Дата:** 2026-06-01  
**Статус:** MVP

## Цель

При отправке запроса снабженец выбирает поставщиков через **вложенный список с галочками**: вся группа или отдельные поставщики.

## User stories

1. Как снабженец, я раскрываю группу и отмечаю всю группу одной галочкой.
2. Как снабженец, я отмечаю только одного поставщика в группе.
3. Как снабженец, после отправки я добавляю ещё поставщика к запросу.
4. Как поставщик, я вижу только запросы, куда меня добавили.
5. Как поставщик, я не вижу других поставщиков и их ответы на тот же запрос.

## UI: дерево

```text
☐ Группа: мск_Опт
    ☐ ООО СтройТепло
    ☐ ИП Иванов
☐ Группа: мск_Производители
    ☑ Роквул-партнёр
```

- Родительская галочка: select all / indeterminate если выбрана часть.
- Один поставщик может быть в **нескольких** группах (отображается в каждой).

## Подсказка категории

Если `tasks.category` совпадает с `category_supplier_group_hints` — подсветить рекомендуемую группу (не автовыбор).

## Модель

При отправке для каждого выбранного `supplier_id`:

```text
INSERT request_suppliers (request_id, supplier_id, status=new, sent_at=now())
deadline_at = sent_at + (app_settings.response_deadline_days * interval '1 day')  -- кал. дни, Europe/Moscow
```

## Изоляция

- Список запросов поставщика: JOIN `request_suppliers` ON `supplier_id`.
- Карточка запроса поставщика: только поля запроса + свои line items, без списка других invites.
- RLS: см. auth-rls.md.

## Критерии приёмки

- [ ] Выбор группы создаёт invite на каждого активного члена
- [ ] Дубликат (request_id, supplier_id) невозможен
- [ ] Добавление поставщика после отправки создаёт новый invite с новым таймером
- [ ] Два поставщика на одном запросе не видят данные друг друга (проверка API + RLS)
