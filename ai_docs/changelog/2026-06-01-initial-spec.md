# Changelog

## 2026-06-01 — Начальная спецификация

### Added

- Полная документация `ai_docs` по продукту zapros (чат 2026-06-01)
- Архитектура: задача → запрос → invite → версии ответа
- Роли: admin, procurement, supplier
- Стек: Next.js 15 + Supabase
- Фичи F001–F008, план MVP, UX канбана
- Решения: таймер 10 р.д. на invite, пауза на уточнении, тред на пару запрос–поставщик
- Три варианта цены в ответе (НДС / нал / без НДС)
- Победа: один поставщик, общая причина брака для остальных

### Decisions

- Yandex PostgreSQL отложен; прототип на Supabase
- Дубли позиций в нескольких запросах разрешены
- Проигранные стадии скрыты в канбане по умолчанию (как Bitrix)

## 2026-06-01 — Ревизия спецификации (обсуждение)

### Changed

- **Принцип «1 запрос = 1 победитель»** зафиксирован явно (разные поставщики → разные запросы)
- **Автозакрытие дублей:** победа закрывает те же позиции в других открытых запросах (`cancelled`)
- **«Ответ получен»** слит с «Есть ответ» (бейдж «не просмотрено» вместо колонки)
- **Таймер:** 10 **календарных** дней (праздники не учитываем), настраивается в `app_settings`; пустой запрос → архив
- **Статус `cancelled`** добавлен в `requests.status` (синхрон с outcome)
- **Правило агрегации** статуса запроса из разнородных invites (приоритеты)
- **Цена сравнения:** нормализация нал→безнал `price_cash / 0.84` (коэффициент в `app_settings`)
- Номер Bitrix **показываем** поставщику; добавлен `request_code` для ссылок
- **Блокировка ответа** в финальных статусах invite
- **CHECK-констрейнты** в БД для XOR (наличие/срок, доставка)
- **Один admin** через частичный уникальный индекс; создание profiles триггером

### Added

- F009 «Уведомления»: email opt-in в ЛК (новый запрос / завершение), очередь `notifications`
- `app_settings` (response_deadline_days, cash_to_noncash_ratio)
